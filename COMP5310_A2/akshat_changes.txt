ASSIGNMENT 2 CHANGES - AKSHAT
================================

Purpose
-------
These changes make the Assignment 2 work reproducible, connect the data pipeline
to the modelling notebook, and add evidence required for modelling comparison,
threshold decisions and error analysis.

1. Data pipeline notebook: 01_data_pipeline.ipynb
--------------------------------------------------
- Completed the pipeline so it now creates the Crowded target.
  Crowded = 1 for FEW_SEATS_AVAILABLE or STANDING_ROOM_ONLY;
  Crowded = 0 for MANY_SEATS_AVAILABLE.
- Added a documented cleaning log explaining the issue, evidence, action and
  impact for whitespace, inconsistent occupancy labels, missing targets,
  duplicate records and timestamp handling.
- Reproduces the Assignment 1 data-cleaning decisions from raw data:
  - trims whitespace in text values;
  - standardises known occupancy label variants;
  - removes 73 records with missing Occupancy Status;
  - removes 250 redundant exact duplicate rows;
  - repairs a time-only timestamp only when its paired timestamp in the same
    row provides a reliable calendar date; otherwise keeps it missing.
- Added final validation assertions:
  - 49,927 cleaned records;
  - no missing Occupancy Status;
  - no exact duplicate rows;
  - approved occupancy categories only;
  - binary Crowded target contains only 0 and 1.
- Saves the model-ready output with a relative path:
  data/processed/train_occupancy_model_ready.csv.
- Added flexible relative raw-data paths so the notebook works in the full
  repository and in the Assignment 2 code-package folder structure.

2. Model-ready data
-------------------
- Added data/processed/train_occupancy_model_ready.csv.
- It contains 49,927 rows and 17 columns, including the validated Crowded target.
- It is the exact handover file that the modelling notebook loads.

3. Modelling notebook: 02_modelling_evaluation.ipynb
-----------------------------------------------------
- Changed the notebook to load train_occupancy_model_ready.csv generated by
  Notebook 1, rather than directly loading an Assignment 1 output.
- Added a target validation check to confirm Crowded agrees with Occupancy Status.
- Added a concise response to Stage 1 data-readiness feedback.
- Documented feature exclusions for leakage/availability reasons:
  Occupancy Status, Occupancy Range, actual arrival/departure timestamps,
  the actual departure-time band, cleaned timestamps, and Crowded itself.
- Added a Trip.Name overlap diagnostic. The stratified random split has 2,919
  trip IDs appearing in both training and test data. Results must therefore be
  described as a benchmark for later observations of known services, not as
  proven performance for entirely unseen services.
- Fixed pandas-version compatibility in categorical feature selection.
- Added an experiment log recording model settings and shared metrics.
- Added Logistic Regression threshold analysis at 0.25, 0.50 and 0.75.
  This makes the false-alarm versus missed-crowding trade-off visible.
- Added code to save confusion-matrix figures for Logistic Regression and
  Random Forest.
- Added error-analysis tables grouping Logistic Regression false negatives and
  false positives by service line and stop station.
